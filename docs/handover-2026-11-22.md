## 3. 未解决问题：鹦鹉和蝙蝠分支的探针回归

- 现象：干净的 main 上探针稳定 769/769。合进鹦鹉（`cf0e63ea`）或者蝙蝠/幻翼（`62f5222f`）之后，探针掉到 695–698/711。最早的两处失败是
  `PROBE FAIL chunk: upper sections are air` 和 `PROBE FAIL play: a later position packet is a correction the probe expected`，后面的 container / durability / falling / crafting / loom / spectator / late 都是连锁失败。
- cl-ambient 的发现：失败时服务端日志里有「Can't keep up! … skipping 40+ ticks」。世界线程落后，玩家移动被原版的「moved too quickly」逻辑拉回。
- 队长的判断：同样的负载下 main 不会出现这种情况，所以这是**新生物让每刻变慢的性能回归**。可能的热点是飞行生物的自然刷怪判定、飞行寻路，或者 debug 构建下每刻的 AI。**探针应该保持原来的严格度**，Probe.java 里只保留两处合理的放宽：自然生成的生物自己发出的环境音不算作门的声音，以及接受原版本来就会发的 `damage_event`。
- 下一步：
  1. 在 main 和分支上分别跑探针服务端，统计 MSPT（每刻耗时），找到热点。
  2. 修掉热点。
  3. 探针在原来的严格度下回到 769/769，然后再合并。
