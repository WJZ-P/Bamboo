## 线程复查摘要（针对第一轮的 `fcc8c50`）

完整报告在本机临时目录，没有进仓库。要点如下。

| # | 严重 | 问题 | 修在 |

| F1 | 致命 | 写盘失败照发 `Written` → 停放的盒子被清掉，`has_chunk` 撒谎 → 下次加载读到空，用模板盖掉改动。复查队员写临时测试实际证实 | `d282d9f` |

- 写盘途中又被要回来能拿到最新的盒子；
- 区域文件写入的崩溃安全。

## 已知但没处理的（可以以后再看）

- 有存档的世界里，进服时盘上的区块走异步读、晚一刻交付，而盘上没有的区块同步用模板，所以远处的区块可能先到。在带存档的世界上跑探针是 642/669，探针是按全新世界校准的，这一项不算回归。等世界生成也走异步以后再统一处理。
- 游戏规则读盘时遇到坏的条目只忽略那一条，官方是整份解码失败、全部退回默认。
- `level.dat` 里 `LevelName`、`allowCommands`、`DataPacks` 等字段写的是默认值或读入时的原值，不是运行时的真值。
- 玩家数据里 Bamboo 没建模的字段（血量、经验、饥饿等）存的是官方默认值。
- `has_chunk` 扫描盘上已有区块时不认 `.mcc` 外置大区块；`Status` 不是 `full` 的区块当成坏块，用模板。
- 剖析数字（约 2 ms / 区块，debug 构建）只量了空模板区块，不代表真实区块。
- `saved_data_samples` 是为对拍放在生产代码里的 `pub fn`，可以挪到 `cfg(test)` 或 feature 后面。
